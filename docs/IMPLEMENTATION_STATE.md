A second, separate initiative from the Content Studio Redesign above -
covers what happens *after* a script locks: production semantic
directives, visual continuity, shot planning, cinematic prompts, clip
materialization/fulfillment, voice/audio/video timeline compilation,
FFmpeg render, and final QC/publish packaging. Explicitly excludes the
Google Flow browser-automation mechanism itself (already implemented,
out of scope here) - phases that route to it are implemented for their
non-Flow paths (stock footage, manual upload) only.

**REUSE audit confirmed by inspection before writing anything new,
against this repository's actual current state (the source plan's own
"Current Repository Position" table was checked against an earlier
baseline and is partially stale - several of its named touch-point
files, e.g. `content_workspace_service.py`/`clip_workspace_service.py`/
`visual_continuity_service.py`, do not exist under those names in this
repo; the underlying capability was found under different names
instead where it exists at all).** Confirmed already covering large
parts of the plan's scope, this session (Content Studio Redesign work):
`ScriptLock`/`ScriptLockService`/`run_script_lock()` (Phase 14) is
this plan's "Final Script Lock + SHA-256 integrity binding"; genre

the "simplified projection" the source plan's own Phase 4 calls out);
a resolved, versioned, quality-scored cinematic prompt package

## How this document is maintained

Every phase of the production-hardening work (see `docs/ARCHITECTURE.md`
for the phase sequence) updates the rows it touches in this file as part
of the same commit that does the work - not as a follow-up. A row that
still says "Missing" or "Partial" after a phase claims to have addressed
it is a bug in that phase's completion, not in this document.
